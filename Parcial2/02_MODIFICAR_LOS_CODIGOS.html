Cuando el enunciado pide MODIFICAR el código

Es de los incisos que más se repiten: el enunciado inventa un método y pide dos cosas, el pseudocódigo en papel y el resultado corriendo el programa. Cayó en 2022 (dos problemas), 2024 y 2025. La profe avisó que lo puede volver a tomar.

La idea clave: casi nunca hace falta reescribir el programa. Los métodos están hechos para que puedas cargar la fórmula nueva desde el menú. Y el programa además te imprime el pseudocódigo ya armado con tu fórmula adentro, que es lo que va en la hoja.

CAMINO A — con la opción "A MEDIDA"

A.1 · Método de INTEGRACIÓN nuevo

integracion.exe → opción 9. Escribís el término de la sumatoria, o sea lo que va adentro de I = Σ [ ... ], usando estas variables:

xi = x_i xi1 = x_(i+1) h = x_(i+1) - x_i fi = f(x_i) fi1 = f(x_(i+1)) fm = f del punto medio i = número de subintervalo n = cantidad total

Ejemplo real (Parcial 2022, Problema 2). El enunciado da:

I = Σ(x_(i+1) − x_i)·f(x_i) + ½·Σ(x_(i+1) − x_i)·(f(x_(i+1)) − f(x_i))

Se escribe igual que está, cambiando los símbolos por los nombres:

(xi1-xi)*fi + 0.5*(xi1-xi)*(fi1-fi)

A.2 · Método de EDO nuevo (multipaso)

edo.exe → opción 9. Escribís lo que va dentro del paréntesis en y(i+1) = y(i) + h·( … ):

fi = f(x_i , y_i) fim1 = f(x_(i−1) , y_(i−1)) fim2 = f(x_(i−2) , y_(i−2)) xi , yi = valores actuales h = paso

Ejemplo real (Parciales 2022 y 2024). El enunciado da y(i+1) = y(i) + h(2f(x_i,y_i) − f(x_(i−1),y_(i−1))), entonces escribís:

2*fi - fim1

Después te pregunta con qué arrancar (el enunciado suele decir "para i = 1 se podría usar Euler"): elegís 1) Euler.

A.3 · Otro esquema de RUNGE-KUTTA

edo.exe → opción 10. El RK4 3/8 del Parcial 2025 ya está en la lista (opción 2). Si te dan otro, elegís 6) escribir los coeficientes a mano y los cargás del esquema general:

k1 = f(xi , yi) k2 = f(xi + a2·h , yi + b21·h·k1) k3 = f(xi + a3·h , yi + b31·h·k1 + b32·h·k2) k4 = f(xi + a4·h , yi + b41·h·k1 + b42·h·k2 + b43·h·k3) y(i+1) = y(i) + h·( w1·k1 + w2·k2 + w3·k3 + w4·k4 )

Para leer los coeficientes del enunciado: lo que acompaña a h en el primer argumento es la a, y lo que acompaña a cada h·k en el segundo argumento es la b. Ejemplo del 2025:

k3 = f(xi + (2/3)h , yi − (1/3)h·k1 + h·k2) → a3 = 2/3 , b31 = −1/3 , b32 = 1

Podés escribir fracciones directamente: 2/3, -1/3, 3/8.

Control que conviene hacer y escribir: los pesos tienen que sumar 1. Si no suman 1, el método no es consistente y copiaste mal algún número. El programa te lo calcula.

A.4 · EDO de ORDEN SUPERIOR (bajar a primer orden)

edo.exe → opción 11. Escribís y'' despejada, usando yp donde dice y'. Ejemplo: y'' + 2y' + 5y = 0 se escribe -2*yp - 5*y. El programa hace el cambio de variable, lo explica y resuelve con Euler o RK4.

B.2 · Ejemplo: agregar un método de integración

En integracion.cpp, el trapecio compuesto es así de corto:

static double calc_trapecio(int n, double *xs, double *fs) { double h = (xs[n] - xs[0]) / n, s = fs[0] + fs[n]; for (int i = 1; i < n; i++) s += 2 * fs[i]; return h / 2 * s; }

Para el método del Parcial 2022 alcanza con copiar esa función debajo, cambiarle el nombre y poner la fórmula nueva:

static double calc_propuesto(int n, double *xs, double *fs) { double I = 0; for (int i = 0; i < n; i++) { double hi = xs[i+1] - xs[i]; I += hi * fs[i] + 0.5 * hi * (fs[i+1] - fs[i]); } return I; }

B.3 · Ejemplo: agregar un método de EDO

En edo.cpp, dentro de paso(...), cada método es un case. Euler es:

case 0: *phi = k1; return y + k1 * h;

Un método nuevo de un solo paso se agrega como un case más. Para uno multipaso no alcanza con paso(), porque hace falta el valor anterior: ahí conviene el camino A.

Orden en que conviene hacerlo en el parcial

1. Leé la fórmula del enunciado y traducila a los nombres de variables (fi, fim1, xi1…).
2. Corré la opción A MEDIDA y anotá el resultado enseguida, antes de ponerte a escribir.
3. Copiá el pseudocódigo que imprimió.
4. Copiá las primeras iteraciones y la tabla.
5. Sacá la captura.
6. Si sobra tiempo: abrí el .cpp, hacé el cambio y mostralo.
